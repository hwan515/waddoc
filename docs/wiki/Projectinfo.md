# 왔닥 (Waddoc)

전화로 예약하면 집 앞까지 찾아오는 방문형 비대면 원격 진료 자율주행 로봇

# 목표(고객들에게 전해주고자 하는 가치)

도서·산간 의료취약지 고령층이 **스마트폰/앱 없이 전화만으로 예약**하고, 예약 시간에 맞춰 **자율주행 차량(로봇)**이 집 앞까지 찾아가 **본인확인·기초 활력징후(vital) 측정·WebRTC 화상진료·재진 예약·처방 상태 추적**까지 이어지도록 하여, **“이동·디지털 장벽을 최소화한 연속 케어 경험”**을 제공한다. 동의 단계는 P1 확장 범위로 분리한다.

# 프로젝트를 하게 된 배경 또는 근거

- **의료 접근성 격차**: 도서·산간 지역은 의료 인력/시설이 부족하고, 고령층은 이동이 어렵다. 결국 “진료를 받기 위해 이동해야 하는 구조”가 치료 지연과 비용 증가로 이어진다.
- **디지털 소외**: 비대면 진료가 확산되어도 고령층은 앱 설치, 회원가입, 인증, 결제, 화상 연결이 큰 장벽이다. “비대면 진료가 가능한데도 이용하지 못하는” 문제가 발생한다.
- **방문형 비대면 진료의 필요성**: 마을회관형(공용 공간) 모델은 이동 부담이 남고, 공용 환경에서 의료 정보가 노출될 수 있다. **개인 단위 방문 + 프라이버시 중심 설계**가 필요하다.
- **기술/운영 검증 필요**: 자율주행·관제·원격진료·센서 데이터 수집이 결합된 서비스는 “기술이 되는가”보다 “운영이 가능한가(안전·복구·기록·책임)”가 핵심이므로, **E2E 데모로 운영 가능성을 검증**할 필요가 있다.

# 주요 기능(목표를 이루기 위한, 또는 보여주기 위한 기능)

## 1) 전화(IVR/TTS) 기반 예약/취소/확인

- 환자는 전화로 진료과 선택(DTMF) → 예약 생성
- 예약 확정/전날 재안내/재진 예약 안내는 **SMS 알림**으로 발송

## 2) 예약 기반 출동 미션 자동 생성 & 배차

- 확정 예약을 기준으로 **환자 좌표(사전 등록) + 슬롯 + 차량 가용성**을 반영해 미션 생성
- 출동은 **스케줄러 자동 트리거 + 운영자 수동 오버라이드** 지원

## 3) Unity 기반 실외 자율주행(집 앞 정차)

- 실시간 vision 및 waypoint 주행으로 지정 geofence(정차 구역) 도착
- 장애물 감지 시 안전정지 / 실패 시 재시도 후 운영자 개입 요청

## 4) 관제(Operator Console): 복구·E-stop·teleop

- 위치/경로/목표지점/ETA/헬스(배터리·네트워크·센서) 표시
- 전방 카메라 스트림 확인
- **E-stop(1초 이내 정지) / teleop takeover / 복구 로그 기록**

## 5) 탑승 후 본인확인·vital 측정 파이프라인

- 본인확인 결과는 감사로그와 TTL 캐시 기준으로 관리하고, 동의는 P1 범위로 분리
- SpO2/혈압/체온 중 최소 2개 측정(또는 더미 입력 fallback)
- 측정값은 MVP에서 저장 선택 범위이며, 필요 시 10초 내 의사 화면 반영

## 6) WebRTC 화상진료 + 종료 처리

- 의사 UI에서 진료 세션 생성 및 연결
- 네트워크 저하 시 재시도/저대역폭 모드 전환 이벤트 표시
- 진료 종료 후 요약 저장, 다음 단계(재진/처방)로 연결

## 7) 진료 요약 기록 & 재진/처방 여부 기록

- 의사 UI에서 진료 요약, 처방 여부(boolean), 처방 메모, 재진 필요 여부(boolean) 기록
- 재진 예약 실제 생성 및 처방 시스템 연계는 P1 확장 범위

## 8) 보호자 포털(조회 중심)

- 예약 상태, ETA, 도착/진료 진행, vital 요약, 진료 요약, 처방 상태 조회

# 프로젝트를 통한 기대 효과

- **디지털 소외 환자의 접근성 확보**: 전화만으로 예약 가능한 UX로 진입 장벽 최소화
- **의료진·운영자 관점의 실운영 가능성 검증**: 관제/복구/기록 중심 E2E 흐름 재현
- **정책·사업화 검토용 데모 자산 확보**: 방문형 비대면 진료 모델의 운영 프로세스·KPI·로그 기반 근거 마련
- **연속 케어 구조 검증**: 재진 예약과 처방 상태 추적을 통해 “1회성 진료”가 아닌 케어 루틴 가능성 확인
